# ACL Permission Consistency Check

检查并清理 `permissions/autogenerated/` 下与 `build.rs` 命令列表不一致的残留 `.toml` 权限文件。

## 背景

`tauri-build` 的 `autogenerate_command_permissions()` 在构建时自动生成权限 `.toml` 文件到 `permissions/autogenerated/` 目录。该目录被 `.gitignore` 忽略。

**问题**：该函数只写不删。当命令从 `build.rs` 的 `commands()` 列表中移除后，旧的 `.toml` 文件仍残留在磁盘上，继续被构建系统读取，导致：
- 本地增量编译能通过（残留文件生效）
- 远程/其他开发者 clean build 失败（没有残留文件，ACL 找不到权限定义）
- 运行时报 `Command xxx not allowed by ACL`

## 覆盖范围

脚本自动发现并清理两类权限文件：

| 类型 | build.rs 位置 | 权限目录 | 命令声明语法 |
|------|--------------|---------|-------------|
| App 级 | `{root}/build.rs` | `{root}/permissions/autogenerated/*.toml` | `.commands(&["cmd1", ...])` |
| 插件级 | `{root}/*/build.rs` | `{root}/*/permissions/autogenerated/commands/*.toml` | `const COMMANDS: &[&str] = &["cmd1", ...]` |

## 使用方法

### 手动执行

```bash
# 在项目 src-tauri 目录下执行
bash .claude/skills/acl-check/scripts/clean-stale-acl.sh examples/api/src-tauri
```

### 集成到构建流程

OHOS 构建已自动集成（`build-ohos.sh` Step 3.5），无需额外配置。

### Claude 对话中调用

在对话中提到 "ACL 检查"、"权限一致性"、"stale permission" 时，Claude 会自动调用此 skill 执行清理。

## 工作原理

1. 扫描 `{root}/build.rs`，提取 `.commands(&[...])` 中注册的所有命令名
2. 扫描 `{root}/permissions/autogenerated/*.toml`，删除不在命令列表中的残留文件
3. 遍历 `{root}/*/build.rs`（插件目录），提取 `const COMMANDS` 中注册的所有命令名
4. 扫描 `{root}/*/permissions/autogenerated/commands/*.toml`，删除不在命令列表中的残留文件

## 输出示例

有残留文件时：
```
  Removing stale permission: old_removed_command.toml (from examples/api/src-tauri/permissions/autogenerated)
  Removing stale permission: stale_cmd.toml (from examples/api/src-tauri/tauri-plugin-sample/permissions/autogenerated/commands)
  Cleaned 2 stale permission file(s).
```

无残留文件时：
```
  All permission files are consistent.
```
