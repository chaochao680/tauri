## Findings

### tauri#25

**F1** 🔴 [OHOS约束] `crates/tauri/src/path.rs:42`

OHOS 特有代码缺少 `cfg(target_env = "ohos")` 包裹，会导致 Windows/macOS/Linux 编译错误。

**Fix**: 添加 cfg gate
```rust
#[cfg(target_env = "ohos")]
pub fn ohos_base_path() -> std::path::PathBuf {
    std::path::PathBuf::from("/data/storage/el2/base/haps/entry/files")
}
```

---

**F2** 🟡 [NAPI] `crates/tauri/src/napi.rs:88`

TSFN 使用了 `callee_handled::<true>()`，会导致参数偏移，ArkTS 侧收到的参数顺序错误。

**Fix**: 改为 `callee_handled::<false>()`
```rust
// ❌ 当前代码
tsfn.callee_handled::<true>().call(FnArgs { data: (arg1, arg2) });

// ✅ 修复
tsfn.callee_handled::<false>().call(FnArgs { data: (arg1, arg2) });
```

---

**F3** 🟡 [平台隔离] `crates/tauri/Cargo.toml:52`

Linux 依赖缺少 `not(target_env = "ohos")` 排除。OHOS 的 `target_os` 是 `"linux"`，会尝试编译 gtk。

**Fix**: 添加 OHOS 排除
```toml
# ❌ 当前代码
[target.'cfg(target_os = "linux")'.dependencies]
gtk = { version = "0.18", features = ["v3_24"] }

# ✅ 修复
[target.'cfg(all(target_os = "linux", not(target_env = "ohos")))'.dependencies]
gtk = { version = "0.18", features = ["v3_24"] }
```

---

**F4** ℹ️ [代码质量] `crates/tauri/src/menu.rs:156`

`unwrap()` 在可能失败的操作上，建议改用 `?` 或 `match` 进行错误处理。

**Fix**: 添加错误处理
```rust
// ❌ 当前代码
let data = mutex.lock().unwrap();

// ✅ 修复
let data = mutex.lock().map_err(|e| format!("Lock poisoned: {}", e))?;
```
